# verification-planning 技能（先设计证据路径，再动手实现）

## 想法

把 OMO Slim 的 `verification-planning` 移植成 DSH 用户级技能：在动一个非平凡的
改动（功能 / bugfix / 重构 / 跨系统变更）之前，先设计一条**项目专属的证据
路径**——从「要建立的结论」出发，找到这个系统能怎样直接证明/限制/推翻它，而不
是默认套一个熟悉的测试方法。

流程（来自上游，保留）：

1. **框定结论**：要成立的行为是什么、哪些条件会让结论不可信、最坏的失败是
   什么；
2. **设计证据路径**：从系统本身的可控输入、可观察效果、状态迁移、不变式、
   边界、产物、可重复/可回滚能力推导候选路径，先发散再选；
3. **设定验证预算**：列出不同结论、各指定一个负责人/证据，选最少且不重复的
   证据；只复用仍然有效的证据（代码/输入/环境/状态未变）；仓库要求的检查
   照做；
4. **必要时造 verification affordance**：当现有系统无法直接暴露决定性事实时，
   造一个最小能力，让相关状态可控、可观察、可重复、可诊断；明确它是临时还是
   长期，临时用完全拆除；
5. **研究未知路径**：依赖不熟悉、变化快的依赖/框架时，先做聚焦调研再决定；
6. **让路径可执行**：准备需要的 support，保持窄、可重复、可检查；
7. **收口**：实现后沿路径取证，报告结论是成立、受限还是被推翻，区分已知事实
   与剩余不确定性。

## 为什么重要

- DSH 的仓库规则里已经有「验证后才能声称完成」，但缺一个**在动手前设计证据**
  的流程；没有它，agent 容易用「跑了现有测试」代替「证明了这个改动」。
- 这也是之前评估里 5 星推荐、纯文本、几乎无 OMO 耦合的技能；和 `simplify`、
  `deepwork`、`codebuddy-second-opinion` 互补。
- 成本低：一条用户级 `SKILL.md`，不需要插件或脚本。

## 来源与移植

- 来源：OMO Slim（[alvinunreal/oh-my-opencode-slim](https://github.com/alvinunreal/oh-my-opencode-slim)）
  的 `verification-planning` 技能（MIT）。
- 保留：上面 7 步的主体、`verification affordance` 概念、按风险/成本/可直接
  检查性选择路径、临时 support 要拆除、最终报告要区分事实与不确定性。
- DSH 化改动：
  - 上游里的 `@explorer` 改成 DSH 的 **subagent / fs 搜索 / web 搜索**（不要
    假设有 explorer 角色）；
  - 和本仓库 AGENTS.md 的「Verify before claiming a plugin works」对齐：
    语法/清单/安装/实时注册/行为五步可以直接作为项目的「仓库要求检查」；
  - 「设定验证预算」里明确：能用一个决定性证据就别重复跑三遍；宽泛测试一次
    就够；
  - 输出建议固定为：`claim → evidence path → 执行结果 → 未验证/限制`，
    避免写成长报告。
- 放置：`~/.dsh/skills/verification-planning/SKILL.md`（用户级技能，rank 400）；
  先不建插件、不加脚本。

## 验收

- 一个「有明确 bug」的改动：技能应给出可复现的失败路径 + 修复后同一路径通过，
  而不是只跑现有测试；
- 一个「只有间接信号」的系统：技能应提出最小 affordance（日志/探针/临时开关），
  并说明它的生命周期；
- 一个小机械改动：技能应明确「普通检查即可」，不强行加证据工程。

## 待解决问题

- 触发词与边界：什么时候自动启用（description）、什么时候应该跳过（小改动）；
  要避免和 `simplify`、`deepwork`、`reflect` 的触发描述打架。
- 输出格式：是否强制 `claim → path → result` 三段；是否要求把证据路径写进
  Plan 文档（和「deepwork」todo 的 pass 计划衔接）。
- 「验证预算」和仓库已有检查（AGENTS.md 五步验证）的关系：不要重复造规则，
  引用即可。
- 是否需要一个 references/ 放常见证据模式（测试、快照、日志、探针、回滚、
  对比运行）；先保持单文件。
- 语言：技能正文用英文还是中文（建议英文正文 + 中文触发词，和现有 DSH 技能
  一致）。
